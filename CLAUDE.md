# Wallet Radar — контекст и правила

## Проект

Pre-trade фаервол для Solana (копи-трейдинг, AI-агенты). Вердикты: `VERIFIED_SAFE` / `LOW_TRUST_WARMING` / `BLOCKED`.

Детекторы: [src/analyzer.ts](src/analyzer.ts), [src/mint.ts](src/mint.ts), [src/defense.ts](src/defense.ts).
Симулятор: [scripts/history-machine.ts](scripts/history-machine.ts).

## Статус аудита (на 2026-09-29)

  - метки перезаписывались вердиктами радара ([scripts/calibrate-ground-truth.ts](scripts/calibrate-ground-truth.ts));

### Разметка

- `ground-truth/labels.jsonl`: 0 подтверждённых меток. `labels_rejected.jsonl`: 23 отклонённых. **НЕ МЕНЯТЬ.**
- Метки прошлого пилота были выдуманы (адреса из памяти модели, время событий сфабриковано).
- Разметка кошельков признана слабой схемой. Целевой подход: исходы **сделок** по ончейн-фактам на t+N дней (пул потерял ≥90% ликвидности, продажа невозможна), система видит только данные до t.

### Открытые проблемы (нужна проверка, не считать фактами)

- `trust.ts:329` вызывает `detectAnomalies` без `mintRisk`, значит в `radar_trust` («gate before you copy») `TOXIC_MINT` не срабатывает. Бенчмарк проверял путь с `mintRisk`. Статус: прочитано в коде, **НЕ ПРОВЕРЕНО запуском**.
- `ground-truth/tools/verify-labels.mjs` сломан: читает `record.label` вместо `record.class`; null-аккаунт проходит; проверка «адрес на странице» бессмысленна для URL эксплореров; нет положительных тестов.
- ~20 из 58 блокировок связаны с одним `freezeAuthority` (`JDq14BWv…`, 19 mint в кэше, префикс `Xs…`). Гипотеза «токенизированные акции» **НЕ ПРОВЕРЕНА**. Слово «легитимный» без источника не использовать.
- `mint-cache.json` не содержит времени получения записей; `scripts/refresh-mint-cache.ts` перезаписывает его.
- USDC/USDT исключены из `TOXIC_MINT` белым списком `MAJOR_MINTS` (`analyzer.ts`) — это не детекция.

## Правила работы

1. Не выдумывай. Не знаешь или не смог проверить: пиши «НЕ ПРОВЕРЕНО».
2. Каждое число сопровождай командой и сырым выводом. Скрипты для отчётных цифр коммить в `scripts/audit/`, не в `scratch/`.
3. Различай «прочитал код» и «запустил команду».
4. Не меняй правила, пороги и метки после просмотра результатов. Любая правка = новый эксперимент с номером; старые результаты сохраняются.
5. Метки берутся только из внешних источников (URL + дата + дословная цитата до 15 слов) и никогда из вердиктов, правил или терминов радара.
6. Не добирай количество слабыми примерами. Меньше записей — допустимый результат.
7. Не редактируй `src/` и `ground-truth/tools/` без явной задачи. Работай по одному этапу, дальше только после подтверждения.
8. Не читай и не печатай `radar.env` и API-ключи.
9. Если задача невыполнима, остановись и скажи об этом.
10. Не подгоняй результат под ожидаемый. Пустой или плохой результат допустим.
