How it works

No heuristics tuned on the demo, no LLM in the decision path — just a learned baseline and nine behavioral rules plus a funding-source check, each with a human-readable reason.

Live, not just a demo

It monitors a watchlist continuously — and the demo above uses real on-chain data.

The radar continuously polls each watched wallet (Helius), rebuilds its baseline, and alerts the moment a rule fires. The demo is a reproduction on historical data, not a confirmed incident: wallet 8XeK5m…eYXU2j, dormant for 173 days, waking with five ≥3×-median swaps on a brand-new venue.

Because mainnet is immutable, re-running the detector on the same historical data reproduces the same verdict — radar replay 8XeK5m… --since 2026-03-11 --until 2026-08-31 → RISK 100/100 · 8 anomalies · 1,307-tx baseline.

Reproduce it yourself with scripts/verify-canon.sh; full write-up in LIVE-DATA.md.

The payoff is the gate before you copy. Copy-trading bots (BonkBot, Maestro, Trojan, Axiom, Photon, BullX) surface wallets to copy — none of them safety-gate the wallet first. radar_trust is that gate: it returns one decision — safe / hold / unknown — with a per-rule reasons[] breakdown, a one-line summary, and a freshness stamp on how recent the data is. An agent about to copy-trade a wallet calls it first and stops, instead of sending money to a wallet that just woke up. And radar_batch gates the whole book at once — it runs the trust check over up to 20 wallets in a single call and returns a ranked shortlist of the ones that are actually safe to copy right now. And once you are copying, the monitoring surface keeps the gate open: the server watches the wallets on your list over HTTP (/watch, /poll, /alerts) and fires a webhook the moment a new anomaly appears — so the gate is continuous, not a one-shot.
