How it works

No heuristics tuned on the demo, no LLM in the decision path — just a learned baseline and eight deterministic rules, each with a human-readable reason.
COLLECT
Helius enhanced txFull per-wallet history, paged, straight from mainnet.
BASELINE
Learn the normalMedian size, venues, programs, cadence — per wallet.
DETECT
8 deterministic rulesEvery anomaly carries structured evidence (tx sigs, numbers) and a per-rule reason.
ACT
Score + alertRisk 0–100 → Telegram, optional LLM digest, MCP call.
DORMANT_ACTIVEreactivated after N days of silence
ACTIVITY_BURSTK+ tx in a short window vs. normal rate
NEW_VENUEfirst swap on an unseen DEX / protocol
LARGE_SWAPswap > N× the wallet's own USD median
CONCENTRATIONrepeated swaps into the same token
NEW_PROTOCOLfirst interaction with an unseen program
TOXIC_MINTunrenounced mint / freeze authority, or top-10 holders controlling ≥60% of supply
REGIME_SHIFTsustained structural break from baseline in swap size, venue diversity, protocol mix, or cadence

Live, not just a demo

It runs 24/7 on a watchlist — and the demo above is real on-chain data.

The radar continuously polls each watched wallet (Helius), rebuilds its baseline, and alerts the moment a rule fires. The demo is a replay of a real event: wallet 8XeK5m…eYXU2j, dormant for 173 days, waking with five ≥3×-median swaps on a brand-new venue.

Because mainnet is immutable, re-running the detector on live data reproduces the same verdict — radar replay 8XeK5m… --since 2026-03-11 --until 2026-08-31 → RISK 100/100 · 8 anomalies · 1,307-tx baseline.

Reproduce it yourself with scripts/verify-canon.sh; full write-up in LIVE-DATA.md.

Built in-window: the Colosseum leap

Beyond the gate — the radar now writes its verdicts on-chain (ZK-compressed), speaks x402, and exposes itself as an agent SDK, a one-tap Solana action, a live dashboard, and a Token-22 transfer hook.
ZK ORACLE
On-chain scan ledgerEvery scan committed to a ZK-compressed Light account (~400x cheaper than a PDA) — the verdict lives on-chain, not in a DB.
AGENT SDK
createRadarClient()A JS/TS client that calls the x402 server, auto-pays USDC, and returns the result with its on-chain ledger signature.
BLINK
One-tap scanA Solana Action / Blink — "Radar scan <addr>" — x402 pay, verdict back, straight from the wallet UI.
HOOK
Scan-on-transferA Token-22 transfer hook scores the transfer on-chain (oracle PDA) — the gate at the moment of transfer.
The payoff is the gate before you copy. Copy-trading bots (BonkBot, Maestro, Trojan, Axiom, Photon, BullX) surface wallets to copy — none of them safety-gate the wallet first. radar_trust is that gate: it returns one decision — safe / hold / unknown — with a per-rule reasons[] breakdown, a one-line summary, and a freshness stamp on how recent the data is. An agent about to copy-trade a wallet calls it first and stops, instead of sending money to a wallet that just woke up. And radar_batch gates the whole book at once — it runs the trust check over up to 20 wallets in a single call and returns a ranked shortlist of the ones that are actually safe to copy right now. And once you are copying, the monitoring surface keeps the gate open: the server watches the wallets on your list over HTTP (/watch, /poll, /alerts) and fires a webhook the moment a new anomaly appears — so the gate is continuous, not a one-shot.
